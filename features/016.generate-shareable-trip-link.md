# Feature 16: Generate Shareable Trip Link

```gherkin
Feature: Generate a shareable trip link
  As a trip creator
  I want to generate a unique link for my trip
  So that I can share it with friends and they can join

  Scenario: Creator generates a shareable link for the first time
    Given I have an active trip that has not been shared yet
    When I choose to invite friends to my trip
    Then the app generates a unique shareable link for my trip
    And I can copy the link to share it

  Scenario: Reopening the invite action shows the existing link
    Given I have already generated a shareable link for my trip
    When I choose to invite friends to my trip again
    Then I see the same link I generated before, not a new one

  Scenario: Creator regenerates the link
    Given I have already generated a shareable link for my trip
    When I choose to generate a new link
    Then a new unique link is created for my trip
    And the previous link no longer works

  Scenario: Starting a new trip invalidates the old trip's link
    Given I have a shared trip with an active link
    When I create a new trip, replacing the old one
    Then the old trip's link no longer works

  Scenario: Editing trip details does not affect the shared link
    Given I have a shared trip with an active link
    When I edit my trip's details
    Then the same link still works
    And it still points to my trip

  Scenario: Link generation fails
    Given I have an active trip that has not been shared yet
    When I choose to invite friends to my trip
    And the app is unable to reach the server
    Then I see a friendly error message
    And my trip remains a private, unshared trip

  Scenario: Double-tapping the generate action does not create multiple links
    Given I have an active trip that has not been shared yet
    When I tap the invite/generate action twice in quick succession
    Then only one valid link is created for my trip

  Scenario: The link persists across a refresh
    Given I have already generated a shareable link for my trip
    When I refresh the page
    Then I still see the same shareable link

  Scenario: Copying the link
    Given I have a shareable link for my trip
    When I tap the copy action
    Then the link is copied so I can paste it elsewhere
```

## Assumptions

1. Generating a link for the first time moves that trip's data from local storage to server-side
   storage; a trip that is never shared stays on local storage exactly as it does today.
2. Only the trip creator's device can reach the invite/generate/regenerate action — enforced
   structurally, since no participant-side view or role exists until feature 019 (Manage Trip
   Participants) is built.
3. There is no cap on how many people can join via one link — deferred to feature 017's own
   analysis, since that concern belongs to joining, not generating.
4. Regenerating the link immediately invalidates the previous link; anyone who only has the old
   link can no longer use it.
5. A link has no expiry date of its own — it is valid until regenerated or until the trip it
   points to is deleted (by starting a new trip).
6. **Resolved 2026-09-13**: "Starting a new trip invalidates the old trip's link" means the old
   trip's server-side rows (trip, its expenses, its participants) are actually deleted — cascaded
   in the same transaction as creating the new local trip — not merely orphaned by clearing the
   share token. This is the only teardown trigger v2 defines; there is no idle-time expiry and no
   separate "delete this shared trip" action (deferred — see Deferred section).

## Out of Scope

- Sharing the link via the device's native share sheet (copy-to-clipboard only)
- Any participant-facing behavior — opening the link and joining is feature 017
- Viewing or managing who has joined via the link — that is feature 019
- Link expiry by time or by number of uses
- Working offline — generating or regenerating a link requires connectivity

## Deferred

- Native OS share-sheet integration — deferred as a nice-to-have enhancement beyond copy-to-clipboard
- A cap on the number of participants who can join via one link — deferred to feature 017
- An explicit, participant-triggered "delete this shared trip" action independent of starting a new
  trip — no such action exists in v2; the only teardown path is the creator starting a new trip
