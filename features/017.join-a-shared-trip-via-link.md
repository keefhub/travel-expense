# Feature 17: Join A Shared Trip Via Link

```gherkin
Feature: Join a shared trip via link
  As a friend
  I want to open a shared trip link and join as a named participant
  So that I can be identified when expenses are attributed to me or split with me

  Scenario: Friend joins a shared trip via a valid link
    Given a friend has shared a valid trip link with me
    When I open the link and enter my name to join
    Then I become a participant on that trip
    And I see the trip's dashboard as a participant

  Scenario Outline: Any number of friends can join the same trip
    Given the trip already has several participants, including one named "Alex"
    When I join using the name "<my name>"
    Then I successfully join as a distinct participant

    Examples:
      | my name |
      | Jordan  |
      | Alex    |

  Scenario: A very long name is limited when joining
    Given I am on the join screen
    When I type a name longer than 50 characters
    Then the name I can submit is limited to 50 characters

  Scenario Outline: Opening a link that no longer leads to a joinable trip
    Given <link condition>
    When I open the link
    Then I see a friendly message explaining the link isn't valid
    And I am not joined to any trip

    Examples:
      | link condition                                                     |
      | the creator has regenerated the link, invalidating my old one      |
      | the creator started a new trip, deleting the one I was invited to  |
      | the link is malformed or was never a real invite                   |

  Scenario: Joining is allowed after the trip's end date has passed
    Given the trip's end date is in the past
    When I open the link and join
    Then I successfully become a participant

  Scenario: Joining a shared trip does not affect my own solo trip
    Given I already have my own solo trip stored on this device
    When I join a friend's shared trip via link
    Then both my solo trip and the shared trip remain available to me

  Scenario: Reopening the link after already joining skips the name prompt
    Given I have already joined this trip once from this device
    When I open the same link again
    Then I am taken straight to the trip as my existing participant
    And I am not asked for my name again

  Scenario: Submitting a blank name is refused
    Given I am on the join screen
    When I try to join with a blank or whitespace-only name
    Then I see an inline error and I am not joined

  Scenario: Joining fails when the server is unreachable
    Given I open a valid link
    When I try to join and the app cannot reach the server
    Then I see a friendly error message
    And no participant record is created for me

  Scenario: Opening the link while offline
    Given my device has no internet connection
    When I open the shared trip link
    Then I see a friendly message that joining requires connectivity

  Scenario: Double-tapping Join does not create duplicate participants
    Given I am on the join screen with my name entered
    When I tap Join twice in quick succession
    Then only one participant record is created for me

  Scenario: Two friends joining at the same time both succeed
    Given two friends open the same link at the same time
    When both submit their names to join
    Then both become distinct participants on the trip
```

## Assumptions

1. There is no cap on the number of participants who can join a trip via one link — the same "no
   cap" position feature 016 deferred to this feature.
2. Participant display names are not required to be unique; two participants may share the same
   name and are still distinguished internally.
3. Display names are limited to 50 characters.
4. Joining is identity-by-device: the joining browser is remembered as "this participant" for this
   trip, with no login or password involved.
5. Joining does not check the trip's date range against today — a friend can join before, during,
   or after the trip's dates.
6. A shared trip joined by a device coexists with that device's own solo (unshared) trip; neither
   is affected by the other, per `OVERVIEW.md` §2's "one owned solo trip, plus any number of shared
   trips" amendment.
7. Joining a shared trip requires connectivity, consistent with `OVERVIEW.md` §2's "shared trips
   require connectivity" amendment; there is no offline queueing of a join attempt.
8. A participant who joins has no elevated permissions — only the trip creator can edit trip
   details or manage the share link (feature 016); this is enforced structurally rather than
   exercised as its own scenario here, since no permission-gated action exists on the joiner's
   side until later features.

## Out of Scope

- Viewing or managing the list of participants who have joined — that is feature 019 (Manage Trip
  Participants).
- Attributing expenses to a payer or a split among participants — that is feature 020.
- Leaving a trip or being removed from it — that is feature 019.
- Any authentication, password, or account system for participants.
- Native OS share-sheet integration for receiving the link (carried over from feature 016's scope).

## Deferred

- A cap on the number of participants per link — considered during this feature's sweep and
  deferred indefinitely (no cap), matching feature 016's original deferral.
- Letting a joined participant edit their own display name after joining — deferred; today the
  name is fixed once joining succeeds.
