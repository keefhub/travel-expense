# Feature 18: Switch Between Multiple Trips

```gherkin
Feature: Switch between multiple trips
  As a user who belongs to more than one trip
  I want to view my trips and switch which one I'm viewing
  So that I can manage all of them without losing access to any

  Scenario: I switch from one trip to another
    Given I belong to more than one trip
    When I open the trip switcher and select a different trip
    Then I see that trip's dashboard and data
    And my other trips remain available in the switcher

  Scenario: The switcher is not needed when I belong to only one trip
    Given I belong to only one trip
    Then no trip switcher is shown

  Scenario: A shared trip is deleted by its creator
    Given one of the trips in my switcher is a shared trip
    When that trip's creator deletes it
    Then the trip no longer appears as available in my switcher

  Scenario: Switching trips with unsaved input warns me first
    Given I have unsaved input on the current trip's expense form
    When I try to switch to a different trip
    Then I am warned that my unsaved input will be lost

  Scenario: Switching to a shared trip while offline
    Given my device has no internet connection
    When I try to switch to a shared trip
    Then I see a friendly message that this requires connectivity

  Scenario: My last-viewed trip is remembered across a refresh
    Given I was viewing a specific trip
    When I refresh the page
    Then I see that same trip again, not a different one

  Scenario: The switcher shows my relationship to each trip
    Given I belong to my own solo trip, a shared trip I created, and a shared trip I joined
    When I open the trip switcher
    Then each trip is labeled with my role: own trip, created, or joined
```

## Assumptions

1. A user's set of trips is the union of: their own solo (unshared) trip, any shared trips they
   created, and any shared trips they joined via link (feature 017) — matching `OVERVIEW.md` §2's
   "one owned solo trip, plus any number of shared trips" amendment.
2. Creating a new solo trip (feature 003) only replaces the solo trip; it never removes shared
   trips the device belongs to from the switcher.
3. The trip switcher UI is not shown at all when the user belongs to exactly one trip — today's
   single-trip experience is visually unchanged.
4. Which trip is "currently selected" is remembered per device across a refresh, independent of
   which trip's data actually lives on the server versus locally.
5. Switching trips while unsaved input exists reuses the same warning behavior as feature 011's
   unsaved-expense warning.
6. A shared trip that becomes unavailable (deleted by its creator) simply disappears from the
   switcher rather than showing as a broken or errored entry.

## Out of Scope

- Leaving a shared trip or removing another participant — that is feature 019.
- Two browser tabs on the same device staying in sync when one switches trips.
- Any server-side concept of a "default" or "last active" trip shared across devices — the
  last-viewed trip is remembered per device only.
- Merging or comparing data across multiple trips at once.

## Deferred

None.
