# Feature 23: Create A Trip As A Shared Trip

```gherkin
Feature: Create a trip as a shared trip
  As a user
  I want my very first trip to be created directly on the server with a share link available immediately
  So that I never need a local-only trip and can invite friends right away

  Scenario: Creator completes trip setup and the trip is created as a shared trip
    Given I have no trip yet and I am on the travel setup screen
    When I select a supported destination country
    And I enter a valid start date and end date
    And I optionally enter a valid trip budget
    And I submit the setup form
    Then the app calculates the trip duration in days
    And the app maps the destination country to the expected trip currency
    And my trip is created as a shared trip on the server
    And I am redirected to my trip's page
    And a shareable link for my trip is already available to copy, with no separate step needed to generate it

  Scenario: Creating a trip without a budget
    Given I am on the travel setup screen
    When I select a supported destination country
    And I enter a valid start date and end date
    And I leave the trip budget blank
    And I submit the setup form
    Then my trip is created without a budget
    And later views of this trip show no remaining-budget calculation

  Scenario Outline: Trip creation accepts boundary-value input
    Given I am on the travel setup screen
    When I enter <start date> as the start date and <end date> as the end date
    And I enter <budget> as the trip budget
    And I submit the setup form
    Then my trip is created successfully

    Examples:
      | start date | end date   | budget   |
      | 2026-10-01 | 2026-10-01 | 500      |
      | 2026-10-01 | 2026-10-10 | 99999999 |

  Scenario Outline: Invalid setup input is refused
    Given I am on the travel setup screen
    When I fill in the setup form with <field> set to <invalid value>
    And I submit the setup form
    Then I see a validation message
    And my trip is not created

    Examples:
      | field    | invalid value                |
      | end date | earlier than the start date  |
      | budget   | zero                         |
      | budget   | a negative number            |
      | budget   | non-numeric text             |

  Scenario: The server rejects the creation for a reason the app's own checks didn't catch
    Given I am on the travel setup screen with otherwise valid input
    When I submit the setup form
    And the server refuses to create the trip
    Then I see a friendly error message
    And my trip is not created

  Scenario: A new trip can duplicate an existing trip's destination and dates
    Given another trip already exists with the same destination and dates as the one I am creating
    When I submit the setup form
    Then my trip is created without any duplicate warning

  Scenario: A user who already has a trip creates another
    Given I already have a created or joined trip on this device
    When I start and complete trip setup again
    Then a new trip is created
    And my existing trip is unaffected
    And both trips are available to switch between

  Scenario: The server is unreachable when submitting trip setup
    Given I am on the travel setup screen with valid input
    When I submit the setup form
    And the app is unable to reach the server
    Then I see a friendly error message
    And my trip is not created
    And the information I entered is still in the form

  Scenario: Double-tapping submit does not create two trips
    Given I am on the travel setup screen with valid input
    When I tap the submit action twice in quick succession
    Then only one trip is created

  Scenario: Refreshing mid-form loses unsaved input
    Given I am on the travel setup screen with some fields filled in but not submitted
    When I refresh the page
    Then my entered input is gone
    And I see the standard browser refresh warning, not a custom one

  Scenario: Trip dates outside the ordinary range are accepted
    Given I am on the travel setup screen
    When I enter a start date in the past and an end date far in the future
    And I submit the setup form
    Then my trip is created without any date-range warning

  Scenario: The share link displays legibly right after creation on mobile
    Given I have just created my trip on a narrow mobile screen
    When I view my trip's page
    Then the shareable link is fully visible or clearly truncated, not cut off or overlapping other content
    And I can copy it with one tap
```

## Assumptions

1. This feature covers trip creation on a device with no trip yet, and also on a device that
   already has a created or joined trip — per the ruling above, the latter simply adds another
   trip to the device's set, since feature 018 already supports switching between multiple trips
   and v1's single-solo-trip-replacement model is being retired.
2. The share link exists from the moment of creation. Feature 016's "invite friends" action is not
   modified by this feature and its file is left as-is (per the retire-v1 decomposition's rejected
   splits); its first-generation scenario becomes vacuous going forward since a link already exists
   before that action is ever used, but reconciling 016's wording is left for whenever 016 is next
   touched, not this feature.
3. Client-side field validation (date range, budget) mirrors feature 001's existing rules
   unchanged; only the persistence target changes from local storage to the server.
4. "Friendly error, entered data retained" on server-unreachable or server-rejected submissions
   reuses the same UX pattern feature 016 already established for its own link-generation failure.
5. No free-text trip-name field exists at creation — destination/country, dates, and budget only,
   consistent with feature 001's original field set.
6. The creating device is treated as the trip's creator for edit, link-management, and
   participant-management purposes, consistent with existing feature 016/019 precedent; no new
   scenario is needed for this here.
7. Trip creation requires connectivity; there is no offline creation path, consistent with the
   retire-v1 initiative's standing-context amendment dropping the offline guarantee for trip
   creation.

## Out of Scope

- Editing trip details after creation (feature 025)
- Managing exchange rates (feature 026) or custom categories (feature 024) at creation time
- Viewing the dashboard/summary for the newly created trip (feature 027)
- Regenerating or re-triggering link generation — already covered by feature 016
- Migrating a pre-existing local (v1) trip — that is feature 030
- Removing v1 routes/components — that is feature 031
- Any offline creation path — creation requires connectivity

## Deferred

None.
