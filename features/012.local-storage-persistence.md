# Feature 12: Local Storage Persistence

```gherkin
Feature: Local storage persistence
  As a traveller
  I want my trip and expenses to be saved locally
  So that I can use the app without a backend or database

  Scenario: App saves trip data locally
    Given the user creates or edits a trip
    When the user saves the trip details
    Then the trip data should be saved in local storage

  Scenario: App saves expense data locally
    Given the user records an expense
    When the expense is saved
    Then the expense should be saved in local storage

  Scenario: App saves category data locally
    Given the user manages custom categories
    When the category data changes
    Then the category data should be saved in local storage

  Scenario: App saves exchange rate data locally
    Given the user enters or updates an exchange rate
    When the exchange rate is saved
    Then the exchange rate data should be saved in local storage

  Scenario: User refreshes the app
    Given the user has saved trip and expense data
    When the browser is refreshed
    Then the app should load the saved data from local storage

  Scenario: App works offline
    Given the user has opened the app before
    When the user is offline
    Then the user should still be able to view saved data
    And the user should still be able to record expenses locally

  Scenario: Local storage is unavailable or full
    Given the browser local storage is unavailable or full
    When the app attempts to save data
    Then the app should show an error message
    And the app should tell the user that the data could not be saved
```
