  then one entry per joined trip), renders nothing below two entries, and otherwise
  shows a header trigger plus a z-50 modal listing every trip as a plain next/link
  labelled "Own trip" / "Created" / "Joined".

Key Decisions:
  - One combined gate (the [UI/Route] tier): no lib/ change and no new route — the

    mount flag `const [mounted, setMounted] = useState(false); useEffect(() =>
    setMounted(true), [])`, which cannot ship: react-hooks/set-state-in-effect is an
    error-level rule in this repo, so lint exited 1. The plan also forbade
    useSyncExternalStore outright, while spec TS-018-02 asked for it — the two
    contradicted each other. The controller authorized the narrow fix: keep the
    plan's design intent (computeEntries still called UNCACHED in the render body,
    no hasRead cache, no "storage" event listener) and replace only the mount flag
    with a module-scope useSyncExternalStore hydration guard (constant true/false
    snapshots, not a data store). plan.md's Step 3 now strikes the old idiom and
    narrows the ban to "not as a data store", both pointing here.
  - REFERENCE.md §4 gained a components/TripSwitcher.tsx row and a reworded
    app/layout.tsx row, by the controller, inside the reviewed diff.
  - The trigger and each entry use the literal `${label} — ${roleLabel}` em-dash
    format the plan mandates for Task 6's selectors. That conflicts with design.md's
    "no em dash in UI copy" rule; the plan's explicit instruction governs, since
    design.md never overrides a spec's functional scenarios.
  - Extra beyond the contract: `import type { JSX } from "react";`, because React
    19's types no longer declare a global JSX namespace and the contract's bare
    `JSX.Element` return type does not compile without it.

Deviations:
