Task 2: [UI] — useUnsavedChangesWarning intercepts in-app navigation while dirty
Completed: 2026-09-11
Commit: 30097bb

Summary:
  Added a click-interception effect to useUnsavedChangesWarning. While
  dirty, a capture-phase document click listener intercepts a same-tab,
  same-origin click on an in-app anchor pointing to a different
  pathname, shows a confirm prompt, and on confirm sets a discarding
  flag before navigating via window.location.assign.

Key Decisions:
  None beyond what the plan specified for the mainline design; two
  guards were added during review (see Deviations).

Deviations:
  Gate B (code-quality review) found two gaps by cross-referencing
  Next.js's own <Link> click handler (node_modules/next/dist/client/
  link.js): the modifier-key guard was missing event.altKey, and there
  was no check for an anchor's download attribute. Both native browser
  gestures (Alt+click save/download, an explicit download link) would
  otherwise have been silently hijacked into an app navigation while
  the form was dirty. Fixed by adding `|| event.altKey` to the guard and
  a `download`-attribute early return. Both gates re-ran clean after the
  fix. plan.md's Task 2 code block was updated to match.

Files Changed:
