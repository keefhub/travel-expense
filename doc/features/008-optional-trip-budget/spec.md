## 1. Business analysis — BA

### 1.1 Purpose

A traveller who sets a spending target wants to see, at a glance, how much of it is left. Most of
this feature's plumbing — entering, saving, and editing a budget — already exists from feature 001
(trip setup) and feature 002 (trip edit). What's missing is the payoff: showing that budget and the
remaining amount somewhere the traveller can actually see it.

### 1.2 Actors & preconditions

- **Actor:** the traveller.
- **Precondition:** an active trip exists. Budget is entered as part of trip setup/edit (features
  001/002), not as a standalone action this feature introduces.

### 1.3 Business rules

| ID | Rule | Source | Status |
|---|---|---|---|
| BR-008-01 | A valid budget entered during trip setup is saved in the trip currency. | Scenario "User sets a budget during trip setup" | **Already implemented** — `lib/trip.ts`'s `submitTripSetup`/`buildAndSaveTrip` already store `budget` on the `Trip` record (no currency conversion at entry; the trip currency is derived from the destination country, and budget is a plain number in that same currency). Verified: `Trip.budget?: number` (`lib/types.ts`), `TripSetupForm.tsx`'s budget field (feature 001). |
| BR-008-02 | Skipping budget entry still allows the trip to be created. | Scenario "User skips budget setup" | **Already implemented** — `validateTripForm` only validates budget when the trimmed input is non-empty; an absent budget is never an error. |

### 1.4 Data touched

- **Reads:** `Trip.budget` (already persisted), the expense list (`lib/storage.ts`'s `getExpenses`,
  already read by feature 006's dashboard section), the exchange-rate list (`getExchangeRates`,
  already read the same way).
- **Writes:** none. This feature is read-only display logic layered on data features 001/002/005/006
  already write.

### 1.5 Edge cases & negative paths

- Budget is set but zero expenses have been recorded yet — `getExpenseTotalsByCurrency([])` already
  returns `[]`, and `getConvertedTotals([], ...)` already returns
  `{ convertedTotal: 0, isComplete: true, missingCurrencies: [] }`, so remaining budget equals the
  full budget. No new handling needed; existing functions already behave correctly at this boundary.
  `[derived]`
- Spending exactly equals the budget (remaining is exactly `0`) — must display `0`, not be treated as
  falsy/hidden. `[derived]`
- The budget is removed via trip edit (BR-008-03's reverse case) — the dashboard must stop showing
  any remaining-budget figure on the next render, the same as if no budget had ever been set
  (BR-008-05). `[derived]`

### 1.6 Out of scope

- Any change to how a budget is entered or validated — features 001/002 already own that, and this
  feature's own Gherkin scenarios for "sets," "skips," and "edits" a budget are already satisfied by
  existing code (see the Status column in §1.3).
- The full dashboard layout (trip summary card, pie chart, last-5-transactions list) — that's feature
  009. This feature only adds to the same placeholder section feature 006 already started
  incrementally building on `app/page.tsx`.
- Any new exchange-rate management behavior — feature 007 already owns entering/editing rates; this
  feature only reads their presence/absence via the already-built `getConvertedTotals`.

## 2. Technical specification — SA

### 2.1 Approach

Add one small pure function, `getRemainingBudget`, to the existing `lib/currency.ts` (which already
owns `ConvertedTotalsResult`, the type this function consumes) — it returns the remaining amount when
every non-trip currency has a rate, or `null` when it can't be computed, mirroring
`ConvertedTotalsResult.isComplete`'s own true/false shape as a value the UI can branch on directly.
`app/page.tsx` gains one more incremental, placeholder-scoped section (following the exact pattern
feature 006 already established there for currency totals): a budget line, and either a remaining
amount or an "can't be fully calculated" note.

### 2.2 Design elements

| ID | Element | Satisfies |
|---|---|---|
| TS-008-01 | `lib/currency.ts` — new `getRemainingBudget(budget: number, convertedTotals: ConvertedTotalsResult): number \| null`. Returns `budget - convertedTotals.convertedTotal` when `convertedTotals.isComplete` is `true`, else `null`. | BR-008-06, 07, 08 |
| TS-008-02 | `app/page.tsx` — inside the existing `trip !== null` branch, a new section rendered whenever `trip.budget !== undefined` (independent of whether any expenses exist yet, unlike the currency-totals section which is gated on `currencyTotals.length > 0`): shows `Budget: {trip.currency} {trip.budget.toFixed(2)}`; computes `getRemainingBudget(trip.budget, convertedTotals)` (reusing the `convertedTotals` this file already computes for feature 006) and, when non-`null`, shows `Remaining: {trip.currency} {remaining.toFixed(2)}` styled with the `--danger` token when `remaining < 0` (BR-008-08); when `null`, shows a `role="status"` note that remaining budget can't be fully calculated yet. Renders nothing at all when `trip.budget === undefined` (BR-008-05). | BR-008-04, 05, 06, 07, 08 |

No design element touches trip setup/edit, storage writes, or any route — confirmed nothing beyond
display logic is needed, per §1.6.

### 2.3 Data model

No new or changed types. `getRemainingBudget` consumes the existing `ConvertedTotalsResult` from
`lib/currency.ts` and `Trip.budget` from `lib/types.ts`, both unchanged.

```ts
// lib/currency.ts — addition only
export function getRemainingBudget(
  budget: number,
  convertedTotals: ConvertedTotalsResult
): number | null {
  return convertedTotals.isComplete ? budget - convertedTotals.convertedTotal : null;
}
```
